# Development log — November 2026

## 2026-11-01 — Data and tokens, proposed

**Done:** [ADR-0008](../decisions/0008-data-and-tokens.md), proposed: what the cloud stores with, and what signs and verifies its tokens.
- **Why now:** the `accounts` module, for ai-platform's app API 1.0, is the first to store anything.
- **The choices:**
  - SQLAlchemy's Core on asyncpg, with queries written where they are used and no ORM sessions;
  - Alembic, a branch for each module, run as a deployment step;
  - Redis for nonces and rate limits;
  - PyJWT for ID tokens, devices' assertions and the cloud's own access tokens;
  - refresh tokens kept as hashes, in PostgreSQL.
- **Tests:** they run against PostgreSQL 18 and Redis in containers, so a developer needs Docker.

**Next:** The owner's decision on ADR-0008. Then the `accounts` module, with Docker Compose for development.

**Decisions:** The owner accepted [ADR-0008](../decisions/0008-data-and-tokens.md) as proposed.
